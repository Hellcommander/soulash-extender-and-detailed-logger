WHAT EXISTS (all tested with synthetic fixtures)
- Proxy BugSplat64.dll: four ABI-checked exports forwarding to BugSplat64_original.dll; opt-in crash logger
  (access violations, module/RVA attribution, 12-frame unwind); debugger fallback (game skips BugSplat under a debugger);
  chain loading of another BugSplat64-compatible extender ([Chain] Next/NextSha256); one proxy instance per process.
- Plugin runtime: SoulashExtender\Plugins\*.dll, interface v3 (messaging, lifecycle messages, game exe hash/base,
  patchMemory, installDetour, installDetourAuto with an x64 length decoder validated against dumpbin on ~170k instructions
  and once on 2.2M game instructions, build-independent anchors findFunctionsReferencingString / findRttiVtable),
  SHA-256 pinning ([Plugins] RequireHash, [PluginHashes]), legacy v2 plugins still load.
- Sandboxed Lua 5.4.9 scripts (SoulashExtender\Scripts\*.lua): whitelisted env, logging-only API (ext.log), memory /
  instruction / wall-clock / native-work caps, escape + hostile-input tests. NO game-state API yet.
- Skill conditions: spec v1 (docs/skill-conditions.md), JSON schema, validator (tools/validate_conditions.py, --emit),
  C++ strict loader + three-valued evaluator (src/conditions.cpp) tested with synthetic snapshots, per-mod discovery of
  <mods>\<mod>\extender\conditions.json at start-up (logged only). Conditional TRIGGER rules: `triggers` array
  ({on:{cast:A}|{attack:true}, cast:B, chance, when}) compile to the engine's own trigger_ability_on_cast / on_attack_cast
  passive effects + a gating condition; fully-native conditions need no evaluator.
- Effects: spec v1 (docs/effects.md; Dredmor spell effects as the reference, mapped effect by effect), composable nodes
  (all / chance / repeat / exact weighted choose / delay / when-gated by skill-conditions) + event triggers (cast, attack,
  kill, turn, damaged, dodge, block, crit). tools/effects_compile.py validates with typed errors and compiles to ability
  JSON + chain passives (trigger_ability_on_cast rows, hoisted restrict_* gates) + milestones + a conditions file +
  effects_report.json (native / evaluator / impossible per node). "Attach" mode adds effects to an existing ability.
  src/effects.cpp: strict loader, same ownership classification, Resolve/ResolveEvent -> {ability, delay} casts for the
  evaluator-owned parts (fail-closed). Start-up discovery of <mod>\extender\effects.json (logged only).
  Exe facts found on the way (pe_xrefs has): `trigger_ability` as an ABILITY key (astral mod) and `trigger_ability_on_turn`
  (hydromancy) are NOT in the exe -> probably silent no-ops; tell the owner. The only verified chain is the passive row.
- Static game analysis: tools/pe_xrefs.py (iat, calls, refs, str, fnstr, has), tools/pe_rtti.py (class name ->
  vtable + virtuals + constructors), tools/asm_fn.py (annotated listings from a dumpbin dump: show/range/grep/callers/

GOTCHAS LEARNED THIS PROJECT
- Windows MSVC: Lua objects must use /MT (the other targets use default static CRT). Long scratch paths break cl (use short dirs).
- The shell tool blocks commands containing the literal word Remove-Item; do file edits/deletes with Python or the editor tools.
- PowerShell `-f` format strings break on JSON braces; use .Replace().
- Test console-subsystem processes started from a windowless parent flake; the game is GUI-subsystem.
- dumpbin /disasm of the 11 MB exe takes ~30 s and ~110 MB; do it in the scratchpad, not the repo.
- Short strings (<=15 chars) are inline immediates in the exe, not .rdata: use `pe_xrefs.py has <key>`.
- Hash-pin comparisons hold the file open with write sharing denied across the load to avoid check/use races.
